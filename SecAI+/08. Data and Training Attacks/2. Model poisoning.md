# Model poisoning

- Attackers target the learned parameters of the model itself
- This direct manipulation alters how the model behaves, even when the training data looks clean
- Attackers exploit the fact that engineers reuse pre-trained models (GPT, etc.): they persuade developers to adopt a maliciously designed foundation model, gaining influence over every downstream system that relies on it
- Malicious models may be hosted on public repositories (e.g. model hubs)
- Uses classic social-engineering and phishing techniques to convince the target that the model is "safe"
- Mitigations:
  - Validate and use trusted foundation models before use
  - Document origin and version
  - Treat the model as a security boundary
  - Verify integrity with checksums or signatures where available
