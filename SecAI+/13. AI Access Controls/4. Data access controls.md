# Data access controls

- Sensitive AI system data can include training data.
  - This can include personal information, proprietary data, internal communications.
  - Access should be restricted to just authorised members of the ML team or automated pipelines used for model development.
  - When sharing data externally for fine tuning, orgs should use encryption, NDAs and privacy-preserving techniques such as anonymisation to reduce exposure.
- Inference and output data also needs strong access control.
  - Prompts and responses can also reveal sensitive details.
  - If these interactions are logged for analysis, these logs should be protected as part of access control measures.
  - Underlying data sources:
    - Many AI systems return data from internal systems, APIs or document repos.
    - These sources should still be subject to an access control check, even if the request has come from an AI model.
    - The AI should authenticate using the identity of the requesting user account or a restricted service account.
- Permissions should be segmented and responses should only return output which the requesting user is authorised to see.
- DLP tools can be used to monitor and protect data as it moves through the AI system.
