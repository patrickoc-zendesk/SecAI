# Limits and quotas

- Simple yet effective means of protecting AI systems.
- Control how often a user or system can interact with an AI model and how much data each interaction can consume.
- Can limit potential damage caused by a malicious or careless user.
- Rate limiting is the foundation of this approach as it defines the number of requests that can be sent per user per interaction.
  - This can prevent DoS, spam, and general model abuse.
  - All users have fair access.
  - Can also deter brute force, jailbreak and model extraction attempts.
- AI workloads are more demanding than traditional computing requirements, and as such standard rate limiting is not sufficient.
  - Requests are dependent on token usage (not all requests are equal).
- AI systems can use token-based rate limiting.
- Limits can be applied to input (context window limits) which prevents excessive text prompts or large file imports.
- Output limits restrict how long a response can be, reducing resources consumed and limiting the chance of data exposure through lengthy answers.
  - If a longer answer is required, the output can be split into multiple separate responses.
- Concurrent request limits can also be used to limit how many queries a user can send at one time.
  - This prevents potential DoS.
- Modality limits can also be applied, restricting the type of inputs and outputs the model can handle.
  - Each modality increases the attack surface.
