# Insecure output handling

- Insecure output handling occurs when an application blindly uses model output without validation or contextual encoding
- Less about factual accuracy and more about the risky assumption that the output is always safe to use
- Downstream components treat model output as trusted, enabling injection into browsers, shells, databases or APIs
- Chatbots may be vulnerable to XSS
  - Can occur if the model includes scripting code and the application renders the output directly in the browser
- Can also lead to CSRF, SSRF, privilege escalation or remote code execution if output reaches back-end systems
- Maps to OWASP Top 10 for LLM Applications (Insecure Output Handling)
- Output should be:
  - Validated
  - Sanitised
  - Contextually encoded for its destination (HTML, SQL, shell)
  - Subject to human or policy checks before executing sensitive actions
- Treat model output as untrusted user input
