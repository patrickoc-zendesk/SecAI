# Insecure plugin design

- Plugins expand what AIs can do by extending the model to external tools, APIs and data sources
- An insecure plugin may issue unauthorised commands (`rm -f`)
- Some insecure plugins may also fail to validate user input
- The core risk is the lack of validation or verification steps to ensure that th AI model should take a certain action.

## Secure plugin design

- Strong access controls
  - least privilege and very all actions against the user/ role permissions
- Validate inputs
  - Well formed that match approved operations and parameters
- Output constraints
  - Limit what the plugin can return or execute (guardrails, alow lists, rate limits, human approval for sensitive actions)
- Audit logging
  - Record prompts, tool calls, parameters, results, destinations
