# Manipulating application integrations

- Attackers target AI integrations
- No flaw is needed to manipulate the behaviour of the model, application or downstream business logic
- This occurs as the application will trust that actions made by an AI model are safe and meet security requirements
- An attacker could do the following:
  - Trigger actions
    - Use a prompt to post an internal note to a public channel or send an unauthorised email
    - This can occur due to verification gaps in the application
  - Misuse read-only access
    - Requests to share private documents, meeting notes, summary of confidential files still follows the read-only access permitted
  - Bypass content filters
    - A user may not have permission to view certain output in the chat interface, but the AI can write to a file through a plugin so the filtered content appears through that path instead
  - Chain actions across tools
    - A prompt instructs the AI to take several small steps, with each individual step appearing harmless but together resulting in a harmful outcome
  - Exploit persistence
    - If the AI can access saved sessions, calendar entries or documents, a prompt planted in one of those places may execute later without direct user involvement
  - Create 3rd party leaks
    - If an AI can send transcripts, summaries or analytics to external systems the attacker may influence what gets sent and sensitive information can leave the environment in a way that looks subtle

## Integration defences

- Must extend beyond basic access controls
- Security reviews need to be conducted
- Role-based permissions following least privilege
- Input validation
- Response filtering
- Record audit logs across the whole prompt chain
