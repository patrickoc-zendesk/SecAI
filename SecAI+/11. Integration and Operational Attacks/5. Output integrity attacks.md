# Output integrity attacks

- Target what comes out of the AI system when an attacker has no direct control over the model
- Techniques that degrade, distort, or disrupt outputs without touching the model architecture or weights
- Different from input attacks (changing the prompt), as these attack the output (changing the answer)
- Examples:
  - Wrapper libraries that inject code
    - Distribute a malicious library that injects code into the output, which then impacts the result
  - Altering RAG summaries
    - In a multistage pipeline, the RAG summary could be altered before being fed into another component, which overall changes what the original output would have been
  - Corrupting output in transit
    - A malicious insider or compromised service on an output path may perform a MitM attack
- This highlights the importance of securing the pipeline from end to end
- Mitigations:
  - Integrity checks (signing/hashing) on outputs between pipeline stages
  - TLS and mutual authentication on internal service paths
  - Verify integrity of wrapper and post-processing libraries
