# 01. Types of AI

> [!info] Exam alignment
> **Domain:** 1.0 — Basic AI Concepts Related to Cybersecurity (17%)
> **Objectives:** 1.1
> **Source notes:** `../01. Types of AI/` (5 files)

## Overview

Objective 1.1 is the vocabulary foundation for the whole exam: it asks you to **compare and contrast various AI types and techniques used in cybersecurity**. Before you can secure AI systems (Domain 2.0) or defend against AI-enabled attacks (Domain 3.0 and [[18. AI-Enabled Attacks|Module 18]]), you have to be able to tell the technologies apart and know what each is good — and bad — at. This module covers the full objective 1.1 "types of AI" list: machine learning, statistical learning, deep learning, transformers, NLP, LLMs, SLMs, generative AI, and GANs. The exam rarely asks "what is X"; it gives a scenario (a detection need, a compliance constraint, an attack artifact) and expects you to pick the right AI type and justify the trade-off.

## How the AI Types Fit Together

- Keep the nesting straight — several exam questions are just this hierarchy wearing a scenario costume:

```
AI
└── Machine learning — algorithms that learn patterns from data and improve over time
    ├── Statistical learning — statistics/probability for prediction + interpretation
    │   (logistic regression, clustering, Bayesian classifiers)
    └── Deep learning — multi-layer neural networks
        ├── Transformers — attention-based architecture; the basis of modern LLMs
        └── Generative AI — creates new content (GANs, diffusion, VAEs)
```

- NLP is a *capability/field* (processing human language), not a layer in this tree — modern NLP is implemented with deep learning, and LLMs are transformer models built for language tasks.
- Generative AI mostly sits on deep learning, but generative methods pre-date it: autoregressive statistical models are the oldest generative approach.
- The exam skill: read a scenario's *problem* (detection, classification, generation), then map it up and down this tree — that mapping is the compare-and-contrast skill objective 1.1 tests.

## Machine Learning

- Machine learning (ML) is a **sub-field of AI** focused on algorithms that improve and learn over time, rather than following fixed, hand-written rules.
- ML models find patterns in large datasets and use those patterns to make **predictions or classifications** on new data.
- Security uses:
  - Detecting anomalous network activity (IDS/IPS, EDR behavioral engines, SIEM analytics).
  - Spam and phishing filtering, malware classification, fraud detection.
- ML adapts to new threats as it learns from new data — but only when it is actually retrained or updated. A model left untouched will decay (see **concept drift** in [[02. Model Training Techniques|Module 02]]).
- Where ML shows up in the security stack: email gateways (spam/phishing scoring), EDR/NGAV behavioral engines, SIEM and UEBA analytics, network IDS/IPS, and fraud engines. Each learns from operational data — which makes those data pipelines an asset worth protecting ([[04. Data Processing|Module 04]]).
- Exam tactic: "ML" is the *general* answer; the specific technique (statistical learning, deep learning, transformer) is the *precise* answer. Read the scenario for how specific it wants you to be.
- The learning paradigms behind ML (supervised, unsupervised, reinforcement) are covered in [[02. Model Training Techniques|Module 02]].

## Statistical Learning

- A **key concept used by ML**: applying statistics and probability to understand data, for both **prediction and interpretation**.
- The exam lists statistical learning as an AI "type" in its own right. Know its signature methods:
  - **Logistic regression** — predicts the *probability* that an input belongs to a class (binary outcome).
    - Security example: scoring whether an email is spam or not spam.
  - **Clustering** — groups similar data points together *without predefined labels*.
    - Security example: monitoring network traffic; normal traffic forms clusters, and anomalous activity stands out as an **outlier**.
  - **Bayesian classifiers** — early statistical NLP (see the NLP section below).

| Aspect | Statistical learning | Machine learning (broader term) |
| --- | --- | --- |
| Emphasis | Understanding data: prediction **and** interpretation | Prediction and classification at scale; algorithms that improve over time |
| Typical methods | Logistic regression, clustering, Bayesian classifiers | Includes statistical learning **plus** deep learning and modern architectures |
| Security examples | Spam probability scoring, traffic outlier baselines | EDR anomaly detection, deep learning malware pattern matching |
| Trade-off | Interpretable — easier to audit, validate, and explain | More capable on complex/high-volume data, often harder to explain |

- Exam distinction: **statistical learning underpins ML** — every logistic regression model is ML, but not every ML model is simple statistical learning. If a scenario stresses *interpretability* or *auditing*, statistical methods are the likely answer; if it stresses *subtle patterns in huge data*, deep learning is.

## Deep Learning

- A **specialized aspect of ML** in which **neural networks** — layered networks of connected nodes — process data.
- "Deep" refers to the **multiple layers** of processing: each layer learns progressively more abstract patterns, from raw bytes to features to concepts.
- Security value: deep learning detects **subtle patterns** that simpler models miss, such as byte-level patterns in malware that hash-based signatures never see.
- Deep learning models are powerful but largely **black-box** — a recurring theme in AI risk (explainability, audit, compliance — see [[20. AI GRC|Module 20]] and [[07. Human-Centric AI Design|Module 07]]).
- Deep learning powers the transformer architecture (below), which in turn powers modern LLMs.

## Transformers

*Not in the source notes as a dedicated file — the objective lists it explicitly, so learn it at security-practitioner depth.*

- A **transformer** is a neural network **architecture** (not a type of learning, not a product) designed to process sequential data **in parallel** and capture **long-range relationships** — how words far apart in a document relate to each other.
- The **attention mechanism** is the core idea: the model weighs the **relative importance of different data elements within a context window**, like selective attention in human perception (following one conversation in a noisy room).
- Attention uses three vectors per element — worth knowing as a concept, not as math:
  - **Query** — "what information am I looking for?"
  - **Key** — "what type of information do I advertise having?"
  - **Value** — "what actual information do I provide when asked?"
- **Multi-head attention**: each attention head analyzes the input from a specific perspective and develops its own specialty during training.
- Variants you may see named in scenarios:
  - **Encoder-only** (e.g., BERT) — understanding/classification tasks.
  - **Decoder-only** (e.g., GPT-family) — text generation; the basis of most LLMs.
  - **Encoder–decoder** — sequence-to-sequence tasks such as translation.
- Transformers replaced recurrent neural networks (RNNs), which processed sequences one element at a time and struggled with long dependencies.
- Transformer architecture is **modular** — it scales to very large sizes and handles **multi-modal data** (text, audio, video) better than older methods.
- Security significance:
  - Transformers trained on **system logs, network traffic, and user behavior** detect anomalous activity by spotting patterns over time and across assets — exposing tactics such as **C2 (command and control) and lateral movement**.
  - **Everything inside the context window can influence the output.** Attention weighs *relevance*, not *trust* or *provenance* — which is exactly why content smuggled into the context (retrieved documents, web pages, user text) becomes an injection vector. See [[09. Prompt and Input Manipulation Attacks|Module 09]].

## Natural Language Processing (NLP)

- NLP enables machines to **process and generate human language**. It is a *field/capability*; an LLM is one kind of model built inside it.
- Evolution (a classic compare/contrast):
  - **Early NLP** used statistical models such as **Bayesian classifiers** — they catch basic patterns (keyword frequency) but miss nuanced, context-dependent meaning.
  - **Modern NLP** uses deep learning (transformers) to capture **meaning and intent**, not just word statistics.
- Security uses:
  - Spam and **phishing detection** — modern NLP catches socially engineered context that keyword filters miss.
  - Log analysis and alert enrichment in the SOC.
  - Parsing and summarizing **threat intelligence reports** at scale.
- Typical NLP tasks in security operations:
  - Classification (spam/phishing/routing), entity extraction (IPs, domains, CVE identifiers from unstructured reports), summarization (incident write-ups), translation (foreign-language intel triage).
- Security significance: attackers use NLP/LLMs for the same advantage — fluent, targeted phishing without grammar tells (see [[18. AI-Enabled Attacks|Module 18]]).

## Generative AI

- **Generative AI produces new content from existing data** — text, images, audio, video, or code — by learning the underlying distribution of the training data and creating new, similar samples.
- Compare and contrast with **discriminative AI**: discriminative models draw *boundaries between classes* (spam vs. not spam); generative models *create new data*. Generative AI is still machine learning — it predicts, then uses those predictions to generate.
- Every **modality** is a different attack surface (and defense tool):
  - **Text generation** (ChatGPT, Claude, Gemini) — phishing at scale, convincing lures.
  - **Code generation** (Copilot, CodeWhisperer, Claude) — malicious scripts, polymorphic malware, and vulnerable-but-plausible code for attackers and defenders alike.
  - **Image/video generation** (DALL-E, Stable Diffusion, Sora, Veo — mostly **diffusion models**) — deepfakes.
  - **Voice synthesis** — vishing and executive-impersonation fraud.
- Defenders use generative AI to:
  - Create **synthetic data** when real data is sparse or too sensitive to retain — e.g., artificial malware samples or simulated network traffic for training detection models.
  - Generate **anonymized stand-ins for sensitive datasets** — synthetic records that retain structural/statistical properties without identifiable personal information, enabling analytics and model training without exposing the underlying data ([[04. Data Processing|Module 04]]).
  - Draft reports, rules, and response playbooks (see [[16. AI-Assisted Security Tools|Module 16]]).
- Attackers use generative AI to:
  - Send **polymorphic malware** — malicious scripts rewritten by AI so they look different on every delivery and evade signature-based detection.
  - Produce **deepfakes, synthetic voices, and convincing phishing campaigns** (see [[18. AI-Enabled Attacks|Module 18]]).
- Other generative architectures worth recognizing:
  - **Autoregressive models** — generate the next element from prior elements; the oldest generative approach and the ancestor of modern LLM text generation.
  - **Diffusion models** — learn to reverse a noise-adding process, generating from pure noise; dominant for image/video.
  - **VAEs (variational autoencoders)** — encoder/decoder pairs that learn latent representations; used to anonymize data and generate realistic synthetic samples.

## Generative Adversarial Networks (GANs)

*Covered in the notes under generative AI; the objective lists GANs explicitly — know the two-network dynamic cold.*

- A GAN is an **architecture used to train generative AI** in which **two models compete against each other**:
  - The **generator** creates synthetic data (images, audio, text).
  - The **discriminator** tries to identify which data is generated by AI versus real.
- Training is an **adversarial game**: each side improves against the other until the generator's output is hard for the discriminator to distinguish from real data. The discriminator's judgments act as feedback that sharpens the generator.
- Why security professionals care:
  - GANs are the classic engine of **deepfakes** — synthetic faces, voice clones, and video impersonations used in fraud, executive impersonation, and disinformation (see [[18. AI-Enabled Attacks|Module 18]]).
  - GAN-generated **synthetic identities** can defeat face-recognition-based authentication.
  - Defensively, GANs generate realistic synthetic samples (attack traffic, rare malware variants) to enrich sparse training data.
- Exam trap: GAN vs. diffusion — both generate images; **GAN = adversarial generator/discriminator pair**, **diffusion = denoising from noise**. Read the scenario for which mechanism is described.

## LLMs vs SLMs

The exam loves this trade-off: **capability vs. cost vs. data control vs. compliance**.

| | LLM | SLM |
| --- | --- | --- |
| Model size | 100s of billions of parameters | Millions to a few billion parameters |
| Training data | Enormous general datasets that can span the entire internet | Fine-tuned on smaller, domain-specific datasets |
| Capabilities | Versatile, with no need for prior examples | Specialized for niche tasks; requires fine-tuning |
| Resource requirements | Substantial computing power; run in large cloud environments | Lightweight; run on-premises, on edge devices, or standard servers |
| Typical deployment | Managed cloud API (SaaS-style — the provider runs the whole stack) | On-premises or edge (self-managed — you secure the stack, like IaaS) |
| Data control | Prompts and data leave your environment | Sensitive data stays in-house |
| Pros | Versatile, powerful, externally maintained | Quick, efficient, cost effective, better privacy |
| Cons | Price, latency, environmental impact, cloud overhead | Not as powerful; needs tuning to balance power and performance |

- The right choice requires balancing **performance, cost, compliance, and security** — the scenario will usually hand you one dominant constraint:
  - **Data residency / regulatory constraint** → SLM on-prem. Running an SLM locally keeps sensitive data in-house and reduces exposure compared with sending prompts to an external cloud LLM.
  - **Versatility with no task-specific dataset** → LLM (it handles zero-shot tasks; an SLM must be fine-tuned).
  - **Cost/latency at scale, edge deployment** → SLM.
  - **Maintenance appetite** → LLM is externally maintained by the vendor; the SLM's tuning and upkeep are yours.
- Cloud service model tie-in: an LLM consumed through a provider's API behaves like **SaaS** (you mainly protect what you put in prompts and set usage policy); an SLM you host behaves closer to **IaaS** (you secure the stack, model weights, and access — see [[13. AI Access Controls|Module 13]] and [[14. Encryption and Data Safety|Module 14]]).
- A **hallucination** — a factually incorrect, nonsensical, or unrelated output — is an inherent LLM behavior (statistical pattern-matching without comprehension), not a bug you patch away. It drives human-in-the-loop requirements in [[07. Human-Centric AI Design|Module 07]] and [[17. AI Security Use Cases|Module 17]].

## Exam Focus

- **Objective wording (learn verbatim):** "Compare and contrast various AI types and techniques used in cybersecurity."
- **Compare/contrast pairs to master:**
  - LLM vs. SLM (capability, cost, data control, compliance, deployment).
  - Statistical learning vs. machine learning (interpretation vs. scale).
  - Deep learning vs. classical ML (layers, subtle patterns, black-box opacity).
  - Generative vs. discriminative AI (creates data vs. classifies data).
  - Transformer vs. RNN (parallel attention vs. sequential memory).
  - GAN generator vs. discriminator (creates vs. judges).
  - Early statistical NLP vs. modern deep-learning NLP (patterns vs. intent).
- **Classic distractor confusions:**
  - Transformer = an *architecture*, not a learning paradigm or a product.
  - GAN vs. diffusion — adversarial pair vs. denoising process.
  - Clustering (unlabeled grouping) vs. classification (labeled prediction).
  - NLP is the field; the LLM is a model built with transformers inside NLP.
  - An SLM is not a "miniature LLM with the same versatility" — it is specialized and needs fine-tuning.
  - Deep learning ⊂ machine learning ⊂ AI — never the reverse.
- **Likely scenario shapes:**
  - Regulated organization that cannot let data leave its environment → SLM on-prem.
  - Detection need with subtle byte-level patterns and no signatures → deep learning.
  - Simple, interpretable spam probability → logistic regression (statistical learning).
  - Unusual traffic with no labels, find the outliers → clustering/anomaly detection.
  - Deepfake or synthetic voice incident → GAN/generative AI attribution → [[18. AI-Enabled Attacks|Module 18]].
  - Detection of C2 or lateral movement across logs over time → transformer-based models.

## Key Terms

| Term | Definition |
| --- | --- |
| Artificial intelligence (AI) | Computer systems performing tasks that would be considered evidence of intelligence if performed by humans |
| Machine learning (ML) | Sub-field of AI: algorithms that learn patterns from data and improve over time |
| Statistical learning | Using statistics and probability to understand data for prediction and interpretation |
| Logistic regression | Statistical method predicting the probability an input belongs to a class (binary outcome) |
| Clustering | Grouping similar data points without predefined labels; anomalies appear as outliers |
| Deep learning | ML using multi-layer neural networks to learn abstract patterns |
| Neural network | Network of connected nodes (neurons) processing data in layers |
| Transformer | Attention-based neural network architecture that processes sequences in parallel and captures long-range relationships |
| Attention mechanism | Technique that weighs the relative importance of elements within a context window |
| Context window | The span of input a model can consider at once; everything in it can influence output |
| NLP | Field enabling machines to process and generate human language |
| Generative AI | AI that produces new content by learning the distribution of existing data |
| Discriminative AI | AI that classifies/distinguishes between data rather than creating it |
| GAN | Architecture with a generator and a discriminator trained adversarially against each other |
| Generator | GAN component that creates synthetic data |
| Discriminator | GAN component that judges whether data is real or AI-generated |
| Diffusion model | Generative model that creates data by reversing a gradual noise-adding process |
| VAE | Encoder–decoder generative model that learns latent representations to produce synthetic data |
| Autoregressive model | Generates each new element based on previously generated elements |
| LLM | Large language model: transformer-based, trained on vast text corpora, generates human-like text |
| SLM | Small language model: millions to a few billion parameters, domain-specialized, runs on-premises or edge |
| Parameters | Adjustable internal values (weights) a model learns during training |
| Multi-modal | Able to process more than one data type (text, audio, video, images) |
| Polymorphic malware | Malware rewritten (e.g., by AI) to look different on each delivery, evading signatures |
| Deepfake | AI-generated synthetic audio/video impersonating a real person |
| Hallucination | Factually incorrect, nonsensical, or unrelated model output |
| Bayesian classifier | Early statistical NLP model that classifies from probabilities and word statistics |
| RNN (recurrent neural network) | Sequential-processing network that maintains hidden state across elements; the architecture transformers replaced |
| Attention head | Specialized transformer component analyzing input from one perspective; heads develop specialties during training |
| Latent space | Low-dimensional space where compressed learned representations (embeddings) of inputs lie |

## Self-Check

1. A bank's fraud team needs a language model tuned to internal fraud terminology, but regulators prohibit sending customer data to external providers. Which model type fits best, and why?
2. An EDR product claims it can flag malicious files that share no known signature or hash. Which AI type makes that plausible?
3. A SOC analyst asks why the model follows instructions found inside a retrieved web page even though the page is "just data." Which architectural property explains this?
4. In a GAN, which component learns to produce increasingly realistic content, and which learns to judge it?
5. Security leadership wants an explainable model that outputs the probability an email is spam, for audit purposes. Which technique is the best fit?
6. A vendor states: "Our transformer is a type of supervised learning that trains on labeled internet text." Identify and correct the two errors.
7. A company chooses a public cloud LLM API over an on-premises SLM. Name two security trade-offs it has accepted.
8. A vendor advertises "GAN-based synthetic traffic generation to train your NDR models." Explain what the GAN is actually doing in that product.

### Answers

1. **SLM, deployed on-premises.** SLMs are fine-tuned on smaller domain-specific datasets, run on standard servers, and keep sensitive data in-house — satisfying the residency constraint. An LLM API would send prompts (and their data) to an external cloud.
2. **Deep learning.** Multi-layer neural networks detect subtle, byte-level patterns in malware that simpler models and signatures miss.
3. **The attention mechanism / context window.** Transformers weigh every element in the context by relevance, not trust or provenance — content retrieved into the context can steer the model, which is the basis of indirect prompt injection ([[09. Prompt and Input Manipulation Attacks|Module 09]]).
4. The **generator** produces synthetic content; the **discriminator** judges real vs. generated. Their adversarial competition drives both to improve — the mechanism behind deepfakes.
5. **Logistic regression (statistical learning).** It predicts the probability of a binary class (spam/not spam) and is interpretable, making it easier to audit and validate.
6. Error 1: a transformer is an **architecture**, not a type of learning. Error 2: modern LLM pre-training is predominantly on unlabeled text (self-supervised); supervised learning requires labeled examples — see [[02. Model Training Techniques|Module 02]].
7. Any two of: prompts and sensitive data leave the organization (data-control loss); reliance on the provider's security and usage policies (SaaS-like shared responsibility); latency/price and vendor lock-in. Gained: versatility and external maintenance.
8. The **generator** produces synthetic (attack-like) network traffic; the **discriminator** judges real vs. generated; the adversarial loop drives realism until the synthetic traffic resembles real attack patterns — giving the NDR model enriched training data without waiting for real incidents.
